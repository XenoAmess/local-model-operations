## 三个内核的快速比较

用户要求快速估计，因此只测代表性注意力调用，没有再生成三条完整视频。保持 BF16、56 头、D128、非因果、无 dropout、无稀疏／量化，三后端使用同一份随机输入、相同 scale。Q 是连续 BTHD，SDPA 使用转置视图；K/V 连续 BHND，FlashInfer 显式 `kv_layout="HND"`。

每种后端每种尺寸预热一次，三轮交错计时取中位数；CUDA event 和墙钟都记录，准备／编译不计入预热后调用耗时。使用实际查询批大小 16,384 和完整 K/V 长度，禁止 fallback；没有加载第二个模型，没有中断 S48，也没有与其它渲染争用 GPU。

| 后端 | 约 5 秒单窗口的 K/V 长度 345,843 | 14 秒整段的 K/V 长度 949,232 |
| --- | ---: | ---: |
| **现用 PyTorch FlashAttention** | **1130.99 ms** | **3105.38 ms** |
| cuDNN BF16 SDPA | 1126.53 ms，延迟少 0.39% | 3091.37 ms，延迟少 0.45% |
| FlashInfer 通用 BF16 FA2 | 1171.93 ms，延迟多 3.62% | 3215.56 ms，延迟多 3.55%；**数值校验失败，不是可用候选成绩** |

这是“一批 Q 对完整 K/V”的时间，不是整层、全片或 5 秒视频生成时间。cuDNN 在表面数字上最快，但不到 0.5% 的差距不构成有实际价值的部署优势；三个样本不用于宣称统计显著。不同视频、Q 大小和布局的排名仍可能变化。

### 正确性检查

- 两个候选都与现用输出**不逐位相同**，不能把本测试称为已经证明无损。
- cuDNN 两种尺寸的抽样相对 L2 误差约 0.32%／0.34%，余弦相似度约 0.999995；末尾 K/V、最后一个头的定向标记检查均完全匹配预期。这是算子数值证据，不是完整视频质量评分。
- FlashInfer 在短尺寸的相对 L2 约 0.34%、标记检查通过；但 949,232 K/V 时相对 L2 约 **84.84%**、余弦约 **0.6424**，最后一头末尾 K/V 标记最大绝对误差约 **0.9911**。这远超普通舍入差异，尽管没有抛出异常、输出也有限。
- 这限定于本机 **FlashInfer 0.7.2.post1、显式 FA2、该超长 HND 布局与形状**。大偏移索引问题是一种待查假设，根因尚未证明；不泛化为所有 FlashInfer 版本、布局或模型都错误。本轮按“快速估计”结束，不额外扩大根因或框架测试。

依赖：Torch 2.12.0+cu130、cuDNN 9.20、FlashInfer 0.7.2.post1。过程使用隔离 launcher，测试主内存上限 16 GiB、聚合仍为 88 GiB，进程 GPU 分配峰值约 27 GiB，远低于整模型测试。首次准备遇到 `ninja` 不在薄 IC 环境 PATH 中，之后仅在测试进程加入已安装的 FastVideo 构建工具路径；没有安装新包或修改正式模型环境。修正后完整短测约 66 秒。

原始计时、墙钟、误差、显存和标记结果见[短测 JSON](../deployments/video-generation/deployment/minimax-h3/dense-kernel-quick-benchmark-20261120.json)，复现入口见[测试脚本](../deployments/video-generation/tools/benchmark_h3_dense_backends.py)。脚本须在当前视频完整交付、GPU 空闲且持有独占锁时通过隔离 launcher 执行，不从普通 shell 直接启动 GPU 工作。
