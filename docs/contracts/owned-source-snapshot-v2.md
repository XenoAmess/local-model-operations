# Explicit owned source snapshot CLI contract v2
This is a new source-only CLI, not a replacement/rerun of the old frozen SQLite request-registry CLI.
Purpose: replace two private hard-coded snapshot scripts with a reusable finite read-only snapshot covering explicitly named READY generations and explicitly named INTAKE tickets/receipts. Metadata observation is not service/process/global liveness or adoption.

Input CLI: python snapshot_owned_source.py ABSOLUTE_MANIFEST_JSON
Public function build_snapshot(manifest) returns the same report mapping; main(argv) prints exactly one complete UTF-8 JSON line and returns 0 for a known finite report, 2 for fatal input/schema/bounds/identity errors. On fatal errors print only a fixed JSON error on stderr, zero stdout. No debug/source/path/error-body leak. Never retry, spawn, sleep, write a file, import caller/dispatcher/DB, mutate metadata, access DB/network/processes/REQUEST/SSE/CONTENT/source body, discover directories, or execute any supplied path.
A partial/unknown event report is useful and printed with exit 0 but evidence_status UNKNOWN; fatal manifest/READY conflict is not a partial snapshot and uses exit 2.

Manifest must be strict JSON object with EXACT keys:
{"schema":"owned-source-snapshot-input/v2","ready_files":[absolute local file strings],"current_ready":one exact ready_files string,"tickets":[{"metadata_path":absolute local file string,"receipt_path":absolute local file string}]}
Bounds: manifest bytes <=1048576; 1..16 distinct normalized READY paths; each READY raw <=65536 and <=256 rows; combined distinct registered IDs <=1024. tickets 0..1024, metadata_path must be unique normalized path; receipt paths unique too. Each ticket/receipt <=65536 bytes. Report serialized UTF-8 <=2097152 bytes before any stdout. Fixed bounds cannot be overridden by bool/int/string CLI options. Reject duplicate JSON keys, NaN/Infinity, invalid UTF-8, recursion failures, non-object/list shapes. Local absolute paths <=4096 characters, no NUL or UNC; reject non-string/relative paths. Filesystem locality/stability/no symlink races are owner premises, not sandbox or atomicity guarantees.
READY schema matches actual dispatcher public record: EXACT eight string keys id,owner,spec_path,task_id,output_path,config_path,machine_id,lane. Each nonempty/non-whitespace and <=4096 chars. id/owner/task_id/machine_id cannot start '-' and UTF-8 bytes <=512, no NUL; lane source/runtime; spec_path/config_path/output_path absolute local paths. Do NOT open spec/config source files. Within one READY, duplicate id/task_id/normalized output is an error. Across READY files, identical id with exact same eight fields is deduplicated preserving first appearance; changed identity or different ID with same task_id/normalized output is an error. current_READY_records is the raw row count in current_ready; registered_distinct_records is cross-generation unique count. Include current_READY_bytes and maximum_READY_bytes=65536; preserve SHA/bytes per supplied READY but no path/body in public report. Track whether each unique registered row belongs to current_ready.
Read only EVENTS.jsonl derived from each unique row's output_path. Reuse the supplied unchanged pool_observer.py public observe_registry(records,max_streams=256), splitting at most1024 records into ordered batches of at most256. Do not reimplement event parsing. The owner v2 extension must aggregate all returned stream intervals with the existing observer sweep at the earliest observed_at_utc across ALL streams; never take max of per-batch peaks or sum per-batch peaks. Any UNKNOWN batch leaves aggregate current/peak/union UNKNOWN/null while observed fragments remain separate. This extension is owner-written after the original v1 native response and receives no new model credit. Do not import old scripts or dispatcher. For no unique records skip observe_registry and emit a known empty HTTP subreport with zero observed_POSTs/ENDs/unpaired/peak, explicitly no streams. For nonempty records preserve the observer report's UNKNOWN/evidence_status/unended_at_cutoff/peak semantics. observe_registry returns streams in input order. Sum observed_POSTs and observed_ENDs from stream metadata even when incomplete, but actual_unpaired_POST_attempts is observer unended_at_cutoff, possibly null. registered_no_observed_POST is count of streams observed_POSTs==0 and explicitly does not prove no actual POST. Include total registered and current-generation no-observed-POST counts; never call them live source count. Do not emit a known zero if an unreadable/malformed event makes observer evidence UNKNOWN.
Tickets: bounded strict parse without importing/executing publisher. Only inspect metadata id/task_id for grouping/registration linkage; no spec/source/task body. Missing/unreadable/invalid metadata yields an entry with metadata_status UNREADABLE or INVALID, id/task_id null, and fixed diagnostics; do NOT abort valid READY snapshot. A valid link requires nonempty string id/task_id <=512 UTF-8 bytes and no NUL. Other metadata fields are irrelevant to this observer (backend owns full schema rejection). Read the explicitly supplied receipt independently even if metadata malformed. Missing receipt status ABSENT; unreadable/invalid strict JSON or stage not nonempty string <=256 chars -> UNREADABLE/INVALID; valid receipt status KNOWN and stage string. Do not copy receipt stderr/error/free text. Ticket/receipt content SHA/bytes may be included when fully read within cap.
Registration linkage is exact id AND task_id against deduplicated READY. valid metadata same id with wrong task_id is not registered and adds IDENTITY_CONFLICT diagnostic. A valid id/task group without matching READY is unregistered; duplicate ticket revisions with same id/task represent one logical identity. Different task_id under same id is a conflict diagnostic and cannot silently merge.
Report intake summary: seen_intake_tickets, distinct_valid_logical_ids (unique id/task pairs), tickets_with_known_receipt, tickets_awaiting_receipt (ABSENT only), preparation_rejected_receipts (stage exactly PREPARATION_FAILED_NO_AUTO_RETRY), invalid_or_unreadable_metadata_tickets, invalid_or_unreadable_receipts, registered_valid_logical_ids, unregistered_valid_logical_ids, and unregistered_stage_counts (stage string for valid unregistered metadata with known receipt; otherwise ABSENT/INVALID/UNREADABLE). These are observations at finite reads; a rejected historical ticket can share a registered logical identity with a later revision. Never subtract rejected ticket count from logical task count. Include per-ticket sanitized row index/status/id/task_id/registered/receipt stage/fixed diagnostics, no raw paths or error text.
Common report: schema="owned-source-snapshot-report/v2", scope="EXPLICIT_READY_AND_TICKETS_ONLY_NOT_GLOBAL", read_started_at_utc/read_finished_at_utc, snapshot_atomic=false, global_source_Runtime_cloud_backend="UNKNOWN_OR_SEPARATE", process_liveness="UNKNOWN", server_receipt="UNKNOWN", actual_socket_or_backend_queue="UNKNOWN", metadata_or_receipt_is_POST_credit=false, candidate_CONTENT_or_DB_access=false. No session/PID/host/operator env is inferred from historical files. This tool does not decide authorization/adoption, dispatch or software success.

V2 owner-only requirement captured after the closed v1 native run: history202 plus target60 can exceed256. All input/output scans remain explicitly bounded; no silent truncation.
