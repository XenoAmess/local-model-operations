# Source intake and preparation lessons

These rules come from finite source-model, preparation and operator records. They describe ownership and evidence; they do not grant a new business action or a global execution sandbox. The [capacity and handoff observation](2026-11-04-source-intake-capacity-handoff.json) preserves the separate model, software and operator stages.

## Let owners publish complete transfers

Give each authorized source owner a standing scope to publish one immutable metadata record per genuine unfinished logical task. Keep the same task identity and new owned output. After transferring execution, the author performs zero direct model POSTs for that transfer. The single intake registers the task; the dispatcher owns execution and retry. A new record does not authorize its author to write READY, a DB, a lease or a caller claim.

Use the execution machine's qualified metadata-only publisher with its explicit interpreter and publish-only mode. In the observed schema, transfer_evidence is a nonempty string linking the immutable authorization. Four invalid direct drops bypassed an already correct publisher type check; they were owner preparation failures before POST. The failed records remain. The correction did not require changing the publisher or retrying model generation.

Publication, accepted metadata, registration, POST_BEGIN and ATTEMPT_END are different events. Report seen tickets, rejected or invalid transfers, unregistered logical tasks, READY without POST and actual unpaired POSTs separately. A registered-only count can hide an intake failure.

## Preserve rows and history at a handoff

Use one queue writer and the machine's qualified OS-owned locking contract. A compare-before-replace check is not a lock. Do not run a manual registrar alongside the intake or infer lock ownership from PID age. Preserve legacy claims until their actual owner exits and its synchronous preparation subprocess has completed.

Changing the READY generation must preserve the same dispatcher and lease histories. Classify each exact old row, including task and normalized output identity. Remove only a proved terminal row with the required released lease; carry missing, pending, claimed, launched or unknown rows in original order. A loop with no owned child handles does not establish that every registered row reached the DB. Archive the old raw bytes before replacement.

Capacity defer is a paired registrar/intake contract: a full projected queue retains the same pending immutable transfer, emits no final failure receipt and backs off. Adopt both files at a controlled sole-writer boundary. Uncertain timeout or nonzero outcomes require reconciliation; they do not establish zero registration or authorize another POST.

In the recorded handoff, only the old intake stopped. Its actual exit was observed before preserving its controls and starting the new locked pair. The dispatcher continued; READY and DB history were unchanged. Stop-to-new-START was 20.178181 seconds of coordination wall. The new START/lock observation did not itself prove a new real task registration or HTTP request.

## Close the model's actual input contract

An ordinary three-message HTTP model does not automatically see the cloud owner's tool declarations. When it writes a consumer of host or external APIs, include the exact relevant declarations, version and capability constraints in its source prefix. Bind which operations start a turn, valid target kinds, return shapes and failure semantics. For the observed host, sending a message did not start an idle worker, while followup could start a non-root task. The local model was not entitled to infer these facts from the cloud owner's tool visibility.

Preserve the original wire when an owner contract was incomplete. Attribute the contract correction and its cost to the owner; evaluate independent model source errors separately. A source-compatible counter opinion does not close an omitted external API contract or prove software behavior.

## Prepare one executable unit at a time

A metadata assignment identifies one SourceReady version and hash, an existing template, the ordered SDK donor, a fresh owned output and its precise first phase. Deliver a complete unit directly to its executor; do not hold it for a whole batch.

Keep preparation helpers within their actual pure-data scope: named-file hashes, named classfile metadata, config, argument files, guards and owned directories. Business execution and first software checks remain with their owner. Resolve only necessary SDK names, preserving classpath order and duplicates. A mistaken top-level versus nested type assumption is an owner preparation error, not evidence of a missing SDK.

For a new output root, validate temporary paths against the fixture task root. Read existing config fields structurally rather than printing thousands of unrelated pin rows. One successful immutable Prepared package can follow several failed preparation attempts; preserve those failures and partial files, correct them in a new revision and do not overwrite the successful package.

## Start work and account for it accurately

A notification to a completed or idle owner is not a new running task. Use the host operation that actually starts the authorized unfinished scope, then consume its START or new output evidence. Keep this coordination delay separate from model or compiler time. Confirmed capacity recovery keeps the same task and the execution machine's user-selected model. A guard refusal remains a separate boundary.

Report source navigation, preparation, failed attempts, successful helper duration, model HTTP, review, software execution, coordination and publication separately. Full wall includes waiting and failures; active labor may remain unknown. A short helper or model response does not replace the complete preparation cost. Overlapping windows cannot be added or described as exclusive labor.

The recorded tooling suite passed four new DATA methods with unchanged pre/post inputs. Its finite process-death and carry cases do not prove all crash or power-loss behavior. The old suite was not repeated. A separate publisher CLI supplement was still pending at this cut. Source review, PreparedOnly, first software pass, formal publication, active adoption and business progress retain their own receipts.
